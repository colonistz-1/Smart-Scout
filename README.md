# ML Project Template

A template repository for structuring machine learning projects. Fork this repo and use it as the starting point for your own work.

The example code trains a classifier on the classic Iris dataset so that every piece of the pipeline (train → evaluate → predict → app) runs out of the box. Replace the example with your own data and models — the *structure* is the part you keep.

## Repository Structure

```
ml-project/
├── data/               Raw & processed data (usually gitignored)
├── src/                Reusable modules (data loading, features, models)
├── scripts/            Entry points: train.py, predict.py
├── notebooks/          EDA-type notebooks
├── config/             Hyperparameters in YAML
├── models/             Saved model weights (>100MB needs Git LFS)
├── outputs/            Figures, metrics, logs
├── app/                Streamlit demo app
│   └── app.py
├── requirements.txt    Pinned versions of packages
├── .gitignore
└── README.md           Setup, usage, results (this file)
```

**Why this layout?**

| Folder | Purpose |
|---|---|
| `data/` | Keep data out of version control. Commit *instructions* for getting the data, not the data itself. |
| `src/` | Code you import. If you copy-paste a function between notebooks, it belongs here instead. |
| `scripts/` | Code you run. Thin entry points that wire together modules from `src/` using settings from `config/`. |
| `notebooks/` | Code you explore with. Notebooks are for EDA and experiments — once something works, promote it to `src/`. |
| `config/` | No magic numbers buried in code. Change hyperparameters without touching Python. |
| `models/` | Trained artifacts. Small models can be committed; anything over 100MB needs [Git LFS](https://git-lfs.com/). |
| `outputs/` | Everything your runs produce: metrics, figures, logs. Reproducible, so gitignored. |
| `app/` | A lightweight demo (Streamlit) so others can interact with your model. |

## Setup

```bash
# 1. Clone your fork
git clone https://github.com/<your-username>/ml-project.git
cd ml-project

# 2. Create and activate a virtual environment
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS / Linux:
source .venv/bin/activate

# 3. Install pinned dependencies
pip install -r requirements.txt
```

## Usage

**Train a model** (reads hyperparameters from `config/config.yaml`, saves the model to `models/` and metrics/figures to `outputs/`):

```bash
python scripts/train.py
```

**Predict on new data** (CSV with the same feature columns used in training):

```bash
python scripts/predict.py --input data/new_samples.csv
```

**Launch the demo app**:

```bash
streamlit run app/app.py
```

**Explore the data**:

```bash
jupyter lab notebooks/01_eda.ipynb
```

## Workflow Tips

1. **Notebook → module → script.** Explore in `notebooks/`, extract working code into `src/`, expose it through `scripts/`.
2. **One config per experiment.** Copy `config/config.yaml`, tweak, and pass it with `--config` to keep experiments comparable.
3. **Never commit secrets or large data.** The `.gitignore` covers the common cases — read it once so you know what is excluded.
4. **Pin your dependencies.** `pip freeze > requirements.txt` after adding a package, so your project runs the same everywhere.
